# Governance

## Purpose

This repository is a governed public operating manual. Governance precedes implementation so that reusable advocacy material can evolve without losing provenance, accountability, or clarity of authority.

## Authority

Humans retain authority for canonical changes. AI systems and automation may recommend, draft, transform, analyse, and validate proposed changes but may not independently approve canonical policy, architecture, or operating rules.

## Change classes

1. **Editorial** — clarity, spelling, formatting, and non-semantic corrections.
2. **Additive** — new examples, templates, methods, evidence, or guidance consistent with existing architecture.
3. **Structural** — changes to schemas, lifecycle, repository architecture, object models, or governance structures.
4. **Canonical** — changes to definitions, principles, authority, required controls, or normative operating rules.

Structural and canonical changes require explicit review before merge.

## Evidence and provenance

Material claims should identify their source or evidentiary basis where practicable. Decisions that materially change the manual should leave a durable record through Git history, pull requests, or decision records.

## Development model

Changes should normally be proposed on a branch and reviewed through a pull request. Direct changes to the default branch should be limited to repository bootstrap or exceptional recovery operations.
